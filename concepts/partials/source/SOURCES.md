## Notes

- **Excerpts.** The sites convert part of each page, the part around its
  partial calls, under the page's front matter:
  - `high-availability`: the section "Recommended instance counts for high
    availability" (lines 98–102): the empty variable `scaling_ert` and the
    call that includes `_oss_scale_table`.
  - `architecture`: "Architecture reference diagrams" up to "System Metrics
    Agents architecture" (lines 12–94), with three partial calls inside
    list items. The two diagrams and their "View a larger version" links
    are left out: images are not this round's question.
  - `enabling-tcp-routing`: "Prerequisites for activating TCP routing" up to
    "TLS for TCP Routing" (lines 57–88): a note held in a variable
    (`mutual_tls_tcp`) and a partial that is the whole of list step 5.
  - `troubleshoot-app-health`: the section "Routing conflict" (lines
    146–165).
  - `routes-domains`: the section "Map a route to multiple apps" (an HTML
    `<h4>`, lines 404–408 of the headings round's copy).
  - `using-vol-services`: the notes round's excerpt of the partial (its
    lines 1–8 and 225–279), now kept in a partial file of its own, as the
    source does.
- **`_oss_scale_table` is the tables round's file.** The tables round copied
  it at `4ac2fb19a0a44534a8469de100af7dd91706e9b7`; the copy here, at the
  survey's commit, is identical (checked with `diff`). The sites reuse the
  tables round's converted partial.
- **Variables excerpt.** `template_variables.yml` keeps the
  `template_variables:` key and the variables the excerpts use, in their
  original order, plus `scale_table` and `roles_table`, two of the ten
  values that name a partial ([survey](../survey/README.md#partial-names-held-in-variables)).
  `scaling_ert` has no value.
- **Published pages.** [`../published/`](../published/) holds the four new
  pages as docs.cloudfoundry.org served them on 2026-10-11, saved with
  `curl`:
  [high-availability](https://docs.cloudfoundry.org/concepts/high-availability.html),
  [architecture](https://docs.cloudfoundry.org/loggregator/architecture.html),
  [enabling-tcp-routing](https://docs.cloudfoundry.org/adminguide/enabling-tcp-routing.html),
  [troubleshoot-app-health](https://docs.cloudfoundry.org/devguide/deploy-apps/troubleshoot-app-health.html).
  `using-vol-services` and `routes-domains` are compared with the notes and
  headings rounds' copies. The published pages are built from whatever
  commit the book used last, not from the commits above; the partials'
  text on them matches the copies (the intent files list what is
  compared).

## Verify

Every copy matches its upstream commit. Run from this directory, with the
repositories cloned next to `cf-docs-rfc-proposal` (`../../../..` is the
directory holding it). No output means every file matches.

```bash
R=../../../..
git -C $R/docs-cloudfoundry-concepts show 97e0d0b25f059c06edd25e30355d26eb93dc560a:high-availability.html.md.erb | diff - high-availability.html.md.erb
git -C $R/docs-cloudfoundry-concepts show 97e0d0b25f059c06edd25e30355d26eb93dc560a:_oss_scale_table.html.md.erb | diff - _oss_scale_table.html.md.erb
for f in architecture _log_cache _syslog_agents; do git -C $R/docs-loggregator show 8e027bac1099b737afe56afa1606b4fcf9d06c94:$f.html.md.erb | diff - $f.html.md.erb; done
for f in enabling-tcp-routing _tcp_modify_ports; do git -C $R/docs-cf-admin show 13826fa7d93eee66902c4a2187a96b884137b58a:$f.html.md.erb | diff - $f.html.md.erb; done
for f in troubleshoot-app-health _routing_conflict; do git -C $R/docs-dev-guide show 9c8df63eb3823011e4e3aff9958c36e25d5190b7:deploy-apps/$f.html.md.erb | diff - $f.html.md.erb; done

```

header) appears verbatim, in order, in the upstream file.
