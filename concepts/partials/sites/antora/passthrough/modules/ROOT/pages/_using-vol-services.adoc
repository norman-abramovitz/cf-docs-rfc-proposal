[[nfs]]
== Create and use NFS volume services

This section describes how to use the NFS volume service.

{app_runtime_abbr} offers two NFS volume services:

* `nfs`: This volume service provides support for NFS volumes using both v3 and v4.x protocols.

* `nfs-legacy` (deprecated): Although it is deprecated, this volume service is still available due to the difficulty of retiring services. If you use this service, it performs exactly the same mount as the `nfs` service. For information about migrating to `nfs`, see <<migrate,Migrate `nfs-legacy` Services to `nfs`>>.

Both services offer a single plan called `Existing`.

++++
<p class="note">
<span class="note__title"><strong>Note</strong></span>
NFS is not available on Windows systems.
</p>
++++

[[create-nfs]]
=== Create an NFS volume service

To create an NFS volume service using the `Existing` plan of the `nfs` service:

. Create an NFS volume service. Run:
+
[source]
----
cf create-service nfs Existing SERVICE-INSTANCE-NAME -c '{"share":"SERVER/SHARE", "version":"NFS-PROTOCOL"}'
----
+
Where:
+
++++
<ul>
  <li><code>SERVICE-INSTANCE-NAME</code> is a name you provide for this NFS volume service instance.</li>
  <li><code>SERVER/SHARE</code> is the NFS address of your server and share.
    <p class="note important">
    <span class="note__title"><strong>Important</strong></span>
    Omit the <code>:</code> that usually follows the server name in the address.
    </p>
  </li>
  <li>
    (Optional) <code>NFS-PROTOCOL</code> is the NFS protocol you want to use. For example, to use NFSv4, set the version to <code>4.1</code>. Valid values are <code>3</code>, <code>4.0</code>, <code>4.1</code> or <code>4.2</code>. If you do not specify a <code>version</code>, the protocol version used is negotiated between client and server at mount time. This usually causes the latest available version to be used.
  </li>
</ul>
<p class="note important">
<span class="note__title"><strong>Important</strong></span>
nfs-volume versions <code>v7.1.45 - v7.1.47</code> ship with a recent version of nfs-utils (a dependency of nfs-volume-service). Recent versions of nfs-utils have stricter option parsing. This leads to an issue with environments that configured the <code>vers=3.0</code> mount option.<br>
NFSv3 does not utilize a MINOR version, but NFSv4 introduced MINOR versions that can be specified.<br>
This has been mitigated by adding auto-correction logic to the nfsdriver process available with nfs-volume <code>>= v7.1.48</code>.
</p>
++++

. Confirm that the NFS volume service appears in your list of services. Run:
+
[source]
----
cf services
----
