= Pushing an app with multiple processes

The Cloud Foundry API (CAPI) V3 supports using a single command to push apps that run multiple processes, such as a web app that has a UI process and a worker process. You can push an app with multiple processes using either a manifest or a Procfile.

For more information about processes, see the http://v3-apidocs.cloudfoundry.org/index.html#processes[CAPI V3 documentation].

[[manifest]]
== Push an app with multiple processes using a manifest

To push an app with multiple processes using a manifest:

[arabic]
. Create a file in YAML format that defines a manifest. Include each process with its start command.
+
This example manifest file defines the app `example-app` with two processes:
+
[source,yaml]
----
version: 1
- name: example-app
  processes:
  - type: web
    command: bundle exec rackup config.ru -p $PORT
    instances: 3
  - type: worker
    command: bundle exec rake worker:start
    health-check-type: process
    instances: 2
----
. Push the app with your manifest by running:
+
[source,console]
----
cf push -f MANIFEST.yml
----
+
Where `MANIFEST` is the filename of your manifest file.

For more information about defining processes with manifests, see link:deploy-apps/manifest-attributes.html#processes[processes] in _App Manifest Attribute Reference_.

[[procfile]]
== Push an app with multiple processes using a Procfile

Procfile support varies depending on the buildpack you use. For example, the Staticfile buildpack requires a Staticfile instead of a Procfile. For more information, see link:../buildpacks/staticfile/index.html[Staticfile Buildpack]

To push an app with multiple processes using a Procfile:

[arabic]
. Create a file named `Procfile` in the root of your app directory. For more information about Procfiles, see the
https://v3-apidocs.cloudfoundry.org/index.html#procfiles[CAPI V3 documentation].
. Add each process and its start command to the Procfile. For example:
+
....
web: bundle exec rackup config.ru -p $PORT
worker: bundle exec rake worker:start
....
. Push the app by running:
+
....
cf push APP-NAME
....
+
Where `APP-NAME` is the name of your app.

By default, the web process has a route and one instance. Other processes have zero instances by default.

[[scale-a-process]]
== Scale a process

To scale an app process:

[arabic]
. Run:
+
....
cf scale APP-NAME --process PROCESS-NAME -i INSTANCE-COUNT
....
+
Where:

* `APP-NAME` is the name of your app.
* `PROCESS-NAME` is the name of the process you want to scale.
* `INSTANCE-COUNT` is the number of instances to which you want to scale the process.

[[view-processes]]
== View processes

To view the processes running as part of an app:

[arabic]
. Run:
+
[source,console]
----
cf app APP-NAME
----
+
Where `APP-NAME` is the name of your app.
+
