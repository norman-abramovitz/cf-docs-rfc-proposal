= Configuring routes and domains

[[create-route]]
=== Create a route

When a developer creates a route using the cf CLI, Cloud Foundry determines whether the route is an HTTP or a TCP route based on the domain. To create a HTTP route, a developer must choose an HTTP domain. To create a TCP route, a developer must choose a TCP domain.

Domains in Cloud Foundry provide a namespace from which to create routes. To list available domains for a targeted organization, use the `cf domains` command. For more information about domains, see link:#domains[Domains].

The following sections describe how developers can create HTTP and TCP routes for different use cases.

[[create-route-w-hostname]]
==== Create an HTTP route with host name

In Cloud Foundry, a host name is the label that indicates a subdomain of the domain associated with the route.
Given a domain
`{app_domain}`, a developer can create the route `example-app.{app_domain}` by specifying the host name `example-app` with the
`cf create-route` command as shown in this example:

[source,console]
----
$ cf create-route shared-domain.example.com --hostname example-app
Creating route example-app.shared-domain.example.com for org example-org / space example-space as username<span>@</span>example.com...
OK
----

[IMPORTANT]
====
The cf CLI `create-route` command does not require the space as an argument. It uses the space you are targeting.
====

This command instructs Cloud Foundry to only route requests to apps mapped to this route for these URLs:

* `http://example-app.{app_domain}`
* `https://example-app.{app_domain}`
* Any path under either of the these URLs, such as `http://example-app.{app_domain}/bar`

[[create-route-wo-hostname]]
==== Create an HTTP route without host name

This approach creates a route with the same address as the domain itself and is permitted for private domains only. For more information, see
link:#private-domains[Private Domains]. +
A developer can create a route from the domain `{private_app_domain}` with no host name with the `cf create-route` command:

[subs=attributes+]
++++
<pre><code>
$ cf create-route {private_app_domain}
Creating route {private_app_domain} for org example-org / space example-space as username<span>@</span>example.com...
OK
</code></pre>
++++

If DNS is configured correctly, this command instructs Cloud Foundry to route requests to apps mapped to this route from these URLs:

* `http://{private_app_domain}`
* `https://{private_app_domain}`
* Any path under either of these URLs, such as `http://{private_app_domain}/foo`

If there are no other routes for the domain, requests to any subdomain, such as `http://foo.{private_app_domain}`, fail.

A developer can also create routes for subdomains with no host names. The following command creates a route from the subdomain
`foo.{private_app_domain}`:

[subs=attributes+]
++++
<pre><code>
$ cf create-route foo.{private_app_domain}
Creating route foo.{private_app_domain} for org example-org / space example-space as username<span>@</span>example.com...
OK
</code></pre>
++++

If DNS is configured for this subdomain, this command instructs Cloud Foundry to route requests to apps mapped to this route from these URLs:

* `http://foo.{private_app_domain}`
* `https://foo.{private_app_domain}`
* Any path under either of these URLs, such as `http://foo.{private_app_domain}/foo`

[[create-route-w-wildcard-hostname]]
==== Create an HTTP route with wildcard host name

An app mapped to a wildcard route acts as a fallback app for route requests if the requested route does not exist. To create a wildcard route, use an asterisk for the host name. +
A developer can create a wildcard route from the domain `foo.{app_domain}` by running:

[subs=attributes+]
++++
<pre><code>
$ cf create-route foo.{app_domain} --hostname '*'
Creating route *.foo.{app_domain} for org example-org / space example-space as username<span>@</span>example.com...
OK
</code></pre>
++++

If a client sends a request to `http://app.foo.{app_domain}` by accident, attempting to reach `example-app.foo.{app_domain}`,
Cloud Foundry routes the request to the app mapped to the route `++*++.foo.{app_domain}`.

[[create-route-w-path]]
==== Create an HTTP route with a path

Developers can use paths to route requests for the same host name and domain to different apps. +
A developer can create three routes using the same host name and domain in the space `example-space` by running: +

[subs=attributes+]
++++
<pre><code>
$ cf create-route {app_domain} --hostname store --path products
Creating route store.{app_domain}/products for org example-org / space example-space as username<span>@</span>example.com...
OK
</code></pre>
++++

[subs=attributes+]
++++
<pre><code>
$ cf create-route {app_domain} --hostname store --path orders
Creating route store.{app_domain}/orders for org example-org / space example-space as username<span>@</span>example.com...
OK
</code></pre>
++++

[subs=attributes+]
++++
<pre><code>
$ cf create-route {app_domain} --hostname store
Creating route store.{app_domain} for org example-org / space example-space as username<span>@</span>example.com...
OK
</code></pre>
++++

The developer can then map the new routes to different apps by following the procedure in
link:#map-route[Map a route to your app].

If the developer maps the first route with path `products` to the `products` app, the second route with path `orders` to the `orders` app, and the last route to the `storefront` app. After this:

* Cloud Foundry routes requests to `http://store.{app_domain}/products` to the `products` app.
* Cloud Foundry routes requests to `http://store.{app_domain}/orders` to the `orders` app.
* Cloud Foundry routes requests to `http://store.{app_domain}` to the `storefront` app.

Cloud Foundry attempts to match routes with a path, and then attempts to match host and domain.

[IMPORTANT]
====
* Routes with the same domain and host name but different paths can only be created in the same space. Private domains do not have this limitation.
* Cloud Foundry does not route requests for context paths to the root context of an app. Apps must serve requests on the context path.
====

[[create-route-with-port]]
==== Create a TCP route with a port

A developer can create a TCP route for `{tcp_app_domain}` on an arbitrary port. This is the default in the cf CLI.

* An arbitrary (random) port is the default. The `--random port` flag is not supported.
+
[source,console,subs=attributes+]
----
$ cf create-route example-space {tcp_app_domain} --random-port
Creating route {tcp_app_domain} for org example-org / space example-space as user@example.com...
OK
Route {tcp_app_domain}:60034 has been created
----

In this example, Cloud Foundry routes requests to `{tcp_app_domain}:60034` to apps mapped to this route.

To request a specific port, a developer can use the `--port` flag, so long as the port is not reserved for another space. To create a TCP route for
`{tcp_app_domain}` on port 60035, run:

[source,console,subs=attributes+]
----
$ cf create-route example-space {tcp_app_domain} --port 60035
Creating route {tcp_app_domain}:60035 for org example-org / space example-space as user@example.com...
OK
----
