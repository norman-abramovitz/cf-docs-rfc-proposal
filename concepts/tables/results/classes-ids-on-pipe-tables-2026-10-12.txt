Classes and ids on pipe tables: probe, 2026-10-12

Question
  Can each tool give a Markdown pipe table (| a | b |) a class (for
  example table-compact) and an id, without rewriting it as a list-table?

Method
- A copy of concepts/tables made outside the repository (APFS clone of
  the working tree at 05:33; the repository was not changed). All builds,
  servers and checks ran in the copy.
- Native syntax first: each candidate written next to a 3 x 3 pipe table
  and compiled with the tool's own Markdown library as installed in the
  sites (Markdoc and Python-Markdown directly; MDX with remark-gfm through
  @mdx-js/mdx evaluate; GitHub through its Markdown API, mode gfm):
    attribute line after the table        {.table-compact #t1}
    the same after a blank line
    attribute line before the table
    attribute on the first header cell     | A {: .table-compact #t1 } |
                                           | A {% .table-compact #t1 %} |
    HTML comment before the table          <!-- table: .table-compact #t1 -->
  Then an HTML wrapper around the table, built in each site.
- Extension: one small change per site that reads the HTML comment
  in the block just above a pipe table and puts its classes and id on
  the <table>. Built with each site's `make check`.
- Test pages (one per site, native mode; Starlight native-plain, where
  its pipe tables are):
    pipe-attrs   case 1  comment on the line above, .table-compact #probe-one
                 case 2  two classes, blank line between comment and table
                 case 3  an unrelated comment above the table
                 case 4  table inside a numbered list item, comment above it
                 case 5  no comment
                 case 6  the comment syntax inside a fenced code block
    pipe-wrapper the table inside an HTML <div> carrying class and id
  The roles table's native pipe form got `<!-- table: #oss-roles-permissions -->`
  on its first line (Docusaurus native, Zensical native and native-plain,
  Starlight native-plain): the id the source has and native mode lost.
- Wide-table check (checks/wide-tables.mjs) run against each site served
  on ports 4610-4612, for the roles pages, and a copy limited to the
  probe pages.

Extension: one comment syntax, three small changes
  Syntax: an HTML comment in the block just above the table, a blank
  line between them allowed:
      <!-- table: .table-compact #oss-roles-permissions -->
      | Activity | Admin | ...
  `.name` adds a class (several allowed), `#name` sets the id.
  Docusaurus  plugins/table-attrs.js (new, 30 lines, 20 of code) and one
              changed line in docusaurus.config.js. The parser drops
              comments, so the plugin reads the source line above the
              table's position and sets the mdast table's hProperties.
  Zensical    table_attrs.py (new, 58 lines, 46 of code) and one line in
              zensical.toml. A preprocessor adds a blank line after the
              comment (a table in a list item must follow one); a
              treeprocessor finds the comment's paragraph (or its raw
              HTML placeholder) just before a <table> and sets class and id.
  Starlight   table-attrs.mjs (new, 37 lines, 24 of code) and two changed
              lines in markdoc.config.mjs. A document transform finds a
              comment node just before a table node and sets its class and
              id attributes; the existing table transform (list-table.mjs)
              renders them.

Side finding (Docusaurus, headings)
  Docusaurus's heading code reads an id from a trailing <!-- #id -->
  comment, but in an .mdx page the comment is dropped before that code
  runs: `## A heading <!-- #probe-heading -->` built as id="a-heading-".

Changes
- Title: a table's title is a bold line above it (Template conventions).
  The comment may sit above the title instead of directly above the
  table, with or without a blank line between comment and title:
      <!-- table: .table-compact #label-requirements -->
      **Label requirements**

      | Part of Label | Length in characters | ...
  Each extension first looks at the block directly above the table; if
  that is not the comment but a paragraph whose whole content is one bold
  run, it looks at the block above that. Only one title is skipped; any
  other block in between stops the search. Class and id go on the table,
  never on the title.
- Zensical: a table given a class by the comment also gets `table`
  (unless named already), so the site's `table.table` rules give back
  the theme's look and scroll box. The source names `.table-compact`
  alone, the same in every tool.
