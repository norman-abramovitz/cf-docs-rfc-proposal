Wide tables: prose width and a continuation cue, 2026-10-12

Method
- The table: _oss_roles_table (12 columns: Activity, then 11 role columns
  of Yes / Org / Space / note markers; 42 body rows). Activity texts are
  11 to 80 characters, median 29; 17 of 42 are 24 characters or fewer,
  23 are 30 or fewer. Longest: "View the status, number of instances,
  service bindings, and resource use of apps".
- Sites: an APFS clone of concepts/tables, built and served outside the
  repository (python3 -m http.server, ports 4620-4627):
    4620-4623  Docusaurus, Zensical, Starlight, Antora, patched builds
    4624-4627  the same, copies of the repository's own builds (before)
  Antora's playbook reads the repository root as a git content source;
  the copy was built from a throwaway git repository in the scratch
  folder holding the same five start paths and source/images.
- Browser: Google Chrome 155.0.8059.39 through playwright-core 1.63.0,
  1280 x 900 window (390 x 900 where noted). The continuation cues were
  also run in Firefox 155.0 and WebKit 26.6 (Playwright's builds 1543 and
  2359, already in the local cache). macOS 27.
- Measured on the first table of roles-table-host in each mode, with CSS
  injected into the built page (exploration) or built in (patched):
    table WxH     the table's width (its scroll width when it is its own
                  scroll box) and height
    box           the scroll box's client width
    col1          width of the Activity column (first header cell)
    lines         text lines in each body row's Activity cell: line boxes
                  counted from Range.getClientRects() over the cell's
                  text nodes; max / median over 42 rows
    wrapped       rows whose Activity cell has more than one line
    total         sum of lines over the 42 rows
    in view       header cells wholly inside the box at scrollLeft 0,
                  and the column the box edge cuts (pixels shown / width)
- "minw-Nch": `table[data-m] tr > :first-child { min-width: Nch }` on the
  roles table only. "compact": every th/td of the roles table at
  font-size 0.85em and half its computed padding.
- Continuation cues: CSS injected into the page; at scrollLeft 0, 240 and
  the end, a 10-pixel strip at the box's right edge and at its left edge
  (right of a sticky column, if any) was compared with the same strip
  without the cue: mean absolute difference of luminance (0-255).
  "first col sticks": the first header cell and a body cell's left edge
  stay at the box's left edge (within 1.5 px) after scrolling 240 px.
- Dark mode: Docusaurus and Starlight by data-theme="dark" on <html>.
  The Zensical site configures no dark palette; the theme's palette
  stylesheet (modern/palette.b27955a4.min.css, shipped with 0.0.69) was
  linked and data-md-color-scheme="slate" set on <body>. The Antora
  default UI has no dark mode.
- Regression: every top-level table on all seven test pages, in every
  mode of every tool (225 tables), measured on the before and patched
  builds at 1280 and 390 pixels: table size and the width of every cell
  in the header row; any change over 1 px is listed.
- Scripts (one-off, not kept in the repository): measure.mjs, cues.mjs,
  regress.mjs, fit-noshadow.mjs, sbar.mjs, shots.mjs, probe-box.mjs.

Why the layout is at its narrowest (computed styles, 1280 px)
  Docusaurus  table: display block, overflow-x auto; the table is the scroll
              box (703 px). Its rows sit in an anonymous table that is
              shrink-to-fit: min(max-content, max(min-content, available)),
              so with min-content (1053) above the available 703 it takes
              min-content. Infima table.pcss L24-L28.
  Starlight   the same: table display block, overflow auto (632 px box).
              markdown.css L135-L139. First and last cells have no start /
              end padding (L145-L150).
  Zensical    classless tables: the theme's script wraps each in
              div.md-typeset__scrollwrap (overflow-x auto, 720 px) >
              div.md-typeset__table (inline-block, shrink-to-fit); the table
              itself is inline-block, overflow auto, max-width 100%.
              Header cells: min-width 5rem = 100 px (root 20 px), border-box,
              padding 16 px each side. Every column's min-content is under
              100 px, so all twelve are 100 px: 1200-1204 px.
              table.table (passthrough) gets the same from the site's
              hints.css, which copies the theme's rules, min-width included.
              table-layout is auto in every mode (computed); nothing sets
              equal widths.
  Antora      the site's table-scroll.js box (792 px, overflow-x auto);
              table.tableblock.stretch is width 100%, and an auto-layout
              table's used width is the larger of its width and the columns'
              minimum: 882 px.

  Sticky, what broke and the fix used for the rows above:
    Zensical classless tables did not stick as first written: the theme
    makes the table a scroll container of its own (overflow auto), so the
    cells stick to the table, which never scrolls. Fixed with overflow:
    visible on the table inside the wrapper.
    Antora (Chrome): the sticky cells hid the collapsed borders of their
    own cells. Docusaurus in Firefox and WebKit: no line between the sticky
    column and the rest (Chrome kept the collapsed border). Starlight has
    no vertical lines, so nothing separates the sticky column. Fixed with
    an inset box-shadow line on the sticky cells (cues/sticky-*.css).
    Docusaurus stripes rows with a translucent colour on the row; an opaque
    sticky cell hides it, so the stripe is laid over the cell's background.
    The Docusaurus fix was re-run in Firefox only (sticks in all modes,
    light and dark; screenshot docusaurus-roles-sticky-firefox-with-separator.png).

  Scrollbar (box height minus client height, px):
    Chrome headless as Playwright starts it passes --hide-scrollbars, so
    the cue runs report 0. Without that switch (sbar.mjs): default 0 in all
    four (overlay); with ::-webkit-scrollbar 10 px in Docusaurus, Zensical
    and Starlight, 0 in Antora, whose UI sets scrollbar-width: thin and
    scrollbar-color on every element (base.css L116-L126). Firefox 155 and
    WebKit 26.6 (headless): 0 with and without the rule.
    Where the scrollbar would be: at the bottom of the box, which ends
    4,010-4,700 px below the bottom of the window when the box's top is
    80 px from the top of the window (before); about 1,750-2,040 px with
    the 24ch floor.
